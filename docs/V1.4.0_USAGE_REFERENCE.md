# CarbideUi NGCC - V1.4.0 Theming Usage

Short reference for theming in V1.4.0: color themes (Ocean, Royal, Ember or your own), the four Carbon
base themes, corner style and button alignment. Section 8 covers the color theme switcher UI, and section 9
lists the other V1.4.0 additions (charts, table add-ons, new components). For components see
[COMPONENT_USAGE_REFERENCE.md](COMPONENT_USAGE_REFERENCE.md) and
[V1.3.0_USAGE_REFERENCE.md](V1.3.0_USAGE_REFERENCE.md). Interactive version in Storybook:
**Guides / Color themes: use and customize** and **Components / Color Theme Presets**.

Everything is standalone and signal based. Import from the package root:

```typescript
import {
  provideNgccTheme,
  provideNgccColorTheme,
  NgccThemeService,
  NgccColorThemeService,
  NgccThemeSwitcher,
  NgccColorThemeSwitcher,
  NGCC_COLOR_THEME_PRESETS,
  auditNgccColorThemePreset,
} from '@assistanz/carbideui';
```

---

## 1. How theming is layered

Three independent settings live on `<html>`. Any combination works, and none needs component changes.

| Setting | Attribute | Values |
| --- | --- | --- |
| Base theme | `data-carbon-theme` | `white` · `g10` · `g90` · `g100` |
| Corner style | `data-corner-style` | `square` (Carbon) · `rounded` · `curved` |
| Button alignment | `data-button-align` | `left` (Carbon) · `centered` |

A **color theme** (Ocean / Royal / Ember / yours) sits on top: a brand color plus tinted background,
layer, text and border colors for each of the four base themes.

---

## 2. Setup

Install, then load the styles once. They include the color, corner and button-alignment rules.

```bash
npm install @assistanz/carbideui @carbon/styles @carbon/charts
```

`src/styles.scss`, registered in `angular.json` as `"styles": ["src/styles.scss"]`:

```scss
@use '@carbon/styles/scss/config' with (
  $use-flexbox-grid: true,
  $font-path: '@ibm/plex'
);

@use '@assistanz/carbideui/styles/carbon';
```

The path must end in `/styles/carbon`. `@use '@assistanz/carbideui/styles'` alone does not resolve in Sass.

## 3. Use Ocean, Royal or Ember

**Step 1.** Set the app default in `src/app/app.config.ts`:

```typescript
import { ApplicationConfig } from '@angular/core';
import { provideNgccColorTheme, provideNgccTheme } from '@assistanz/carbideui';

export const appConfig: ApplicationConfig = {
  providers: [
    provideNgccTheme({
      defaultTheme: 'g10',           // 'white' | 'g10' | 'g90' | 'g100'
      defaultCornerStyle: 'rounded', // 'square' | 'rounded' | 'curved'
      defaultButtonAlign: 'left',    // 'left' | 'centered'
    }),
    provideNgccColorTheme({ defaultPreset: 'ocean' }), // 'ocean' | 'royal' | 'ember' | your own
  ],
};
```

**Step 2.** `src/main.ts`:

```typescript
bootstrapApplication(AppComponent, appConfig);
```

The theme is applied when the app starts. You do not need a switcher on the page, and nothing has to
inject a service first.

| Preset | Brand | Neutrals |
| --- | --- | --- |
| `ocean` | teal `#007d79` | cool blue-green |
| `royal` | purple `#6929c4` | violet |
| `ember` | burnt orange `#ba4e00` | warm earth |

- The preset is the starting point only for users with **no saved choice**. A user's own customization
  always wins, and **Reset to Defaults** returns to your preset, not to plain Carbon.
- Every preset covers all four base themes, so it follows the active base theme.
- Contrast: text and secondary text are at least 7:1 (AAA) on the background and on layers, and control
  borders at least 3:1, in every preset and base theme.
  Known exception: at the AAA target, Carbon's own secondary button on Gray 90 / Gray 100 is 5:1.

Apply one in code instead (replaces current customization):

```typescript
const colorTheme = inject(NgccColorThemeService);
colorTheme.applyPreset('royal');
inject(NgccThemeService).setTheme('g90'); // base theme is independent
```

Let users choose:

```html
<ngcc-theme-switcher />        <!-- base theme, corner style, button alignment -->
<ngcc-color-theme-switcher />  <!-- brand color, base-theme colors, WCAG report -->
```

```typescript
@Component({ imports: [NgccThemeSwitcher, NgccColorThemeSwitcher] /* … */ })
```

To build your own picker, loop over `NGCC_COLOR_THEME_PRESETS` and call `applyPreset(preset)`.

## 4. Create your own customization

### A. A reusable preset (recommended)

A brand color plus any of seven colors per base theme: `background`, `layer-01`, `layer-02`,
`text-primary`, `text-secondary`, `border-subtle`, `border-strong`. Anything left out stays Carbon's.

```typescript
export const FOREST: NgccColorThemePreset = {
  id: 'forest',
  name: 'Forest',
  description: 'Green brand with green-tinted surfaces',
  brandColor: '#198038',
  themeColors: {
    white: { background: '#f9fbf9', 'layer-01': '#ecf3ef', 'border-strong': '#4f725b' },
    g100: { background: '#0f1a13', 'layer-01': '#17261c', 'border-strong': '#82a18c' },
    // g10, g90 …
  },
};

// Check it before shipping. An empty array means it passes.
auditNgccColorThemePreset(FOREST, 'AA');
auditNgccColorThemePreset(FOREST, 'AAA');
// → [{ theme, check, foreground, background, ratio, required }, …]

provideNgccColorTheme({ defaultPreset: FOREST }); // app default
colorTheme.applyPreset(FOREST);                   // or apply at runtime
```

Audit rules: text and secondary text on the background and on both layers need 4.5:1 (AA) or 7:1
(AAA); the control border needs 3:1 on the background and layer 01. The brand color is not audited
because it is contrast-adjusted for each base theme automatically.

### B. Small tweaks at runtime

```typescript
colorTheme.updateBrandColor('#d02670');                    // returns false if not valid hex
colorTheme.setThemeColor('g90', 'background', '#1c1f26');  // per base theme
colorTheme.resetThemeColors('g90');                        // one theme
colorTheme.resetThemeColors('g90', 'background');          // one color
colorTheme.resetOverrides();                               // everything, back to your default
```

### C. Save, restore and export

```typescript
const saved = colorTheme.exportConfig();  // plain JSON, e.g. for a user profile
colorTheme.importConfig(saved);           // validated; false if invalid
colorTheme.toCss();                       // ready-to-paste CSS custom properties
```

## 5. Base theme, corners and button alignment (from code)

```typescript
const theme = inject(NgccThemeService);
theme.setTheme('g100');
theme.setCornerStyle('rounded');     // controls 4px, containers 8px
theme.setButtonAlign('centered');    // label and icon centered, 8px gap
theme.setFollowSystem(true);         // follow the OS light/dark setting
```

| Corner style | Buttons | Inputs | Containers |
| --- | --- | --- | --- |
| `square` | 0 | 0 | 0 |
| `rounded` | 4px | 4px | 8px |
| `curved` | pill | 24px | 16px |

Defaults for first-time users: `provideNgccTheme({ defaultTheme, defaultCornerStyle, defaultButtonAlign,
followSystem })`. Signals: `theme()`, `cornerStyle()`, `buttonAlign()`, `isDark()`, `followSystem()`.

---

## 6. Behaviour to know

- **Persistence:** choices are saved to local storage (`ngcc-theme`, `ngcc-theme-color`), validated on
  load, and synced across browser tabs. Change the storage with `provideNgccTheme({ storage: 'session' | 'none' })`.
- **Migration:** old values are upgraded automatically. A saved `rounded`, `curved` or `centered` theme
  becomes White plus that corner style or alignment, and the old session-storage key is picked up once.
  `setTheme('rounded')` still works and now only changes the part it names.
- **Brand color:** `defaultColor` on `<ngcc-color-theme-switcher>` sets only the brand color. Prefer
  `provideNgccColorTheme({ defaultPreset })`.
- **Accessibility report:** `colorTheme.accessibilityReport()` checks the active theme live and flags
  text colors you customized that fall below the target.

## 7. Token names

The color theme switcher groups colors into the same sections. Select a color and the panel on the right lists
these tokens, each with a Copy button (see section 8).
`NgccThemeColorToken` is the key you pass to `setThemeColor(theme, token, color)`.

| Section | Color (`token`) | Custom properties it drives |
| --- | --- | --- |
| Brand | brand color (`updateBrandColor`) | `--cds-interactive`, `--cds-border-interactive`, `--cds-button-primary` (+ hover, active), `--cds-button-tertiary`, `--cds-icon-interactive`, `--cds-highlight`, `--cds-chart-color-1 … 12` |
| Surfaces | `background` | `--cds-background`, `--cds-background-hover` |
| | `layer-01` | `--cds-layer`, `--cds-layer-01`, `--cds-field`, `--cds-field-01`, `--cds-layer-hover`, `--cds-layer-hover-01` |
| | `layer-02` | `--cds-layer-02`, `--cds-field-02`, `--cds-layer-hover-02` |
| Text & icons | `text-primary` | `--cds-text-primary`, `--cds-icon-primary` |
| | `text-secondary` | `--cds-text-secondary`, `--cds-icon-secondary` |
| Borders | `border-subtle` | `--cds-border-subtle`, `--cds-border-subtle-00` … `-03` |
| | `border-strong` | `--cds-border-strong`, `--cds-border-strong-01` … `-03` |
| Status | `support-error` | `--cds-support-error`, `--cds-support-01`, `--cds-text-error`, `--cds-button-danger-primary` (+ hover, active) |
| | `support-warning` | `--cds-support-warning`, `--cds-support-03` |
| | `support-success` | `--cds-support-success`, `--cds-support-02` |
| | `support-info` | `--cds-support-info`, `--cds-support-04` |
| Links & focus | `link` | `--cds-link-primary`, `--cds-link-primary-hover`, `--cds-link-visited`, `--cds-link-01` |
| | `focus` | `--cds-focus` |

**Auto-adjusted colors** (status, link, focus): the service builds their whole token family and
contrast-adjusts it for the active base theme and your WCAG target, so the applied value can differ
slightly from the one you pick. Set them with `setThemeColor()` or a preset's `themeColors`. Do not
override those CSS variables by hand, because that skips the adjustment. Their default is derived from the
brand color, and setting one back to that value removes the override.

```typescript
colorTheme.setThemeColor('white', 'support-info', '#0072c3'); // info color for the White theme
colorTheme.setThemeColor('g90', 'link', '#78a9ff');
```

Corner tokens (set by `data-corner-style`): `--ngcc-radius-button`, `--ngcc-radius-input`,
`--ngcc-radius-container`. Attributes on `<html>`: `data-carbon-theme`, `data-corner-style`,
`data-button-align`. Storage keys: `ngcc-theme`, `ngcc-theme-color`.

Without TypeScript, override the surface, text and border colors in plain CSS, after the `@use` lines.
Keep the `:root[data-carbon-theme='…']` selector so it beats Carbon's own rules:

```scss
:root[data-carbon-theme='white'] {
  --cds-background: #f9fbf9;
  --cds-layer: #ecf3ef;
  --cds-layer-01: #ecf3ef;
  --cds-field: #ecf3ef;
  --cds-field-01: #ecf3ef;
}
```

`NgccColorThemeService.toCss()` returns everything the service writes.

## 8. The color theme switcher

`<ngcc-color-theme-switcher />` shows one section at a time:

| Tab | What it holds |
| --- | --- |
| **Colors** | A list of the 13 customizable colors (swatch, name, hex), grouped as Surfaces, Text & icons, Borders, Status colors, Links & focus. Select one to edit it on the right: color picker, hex field, Reset, its **CSS tokens** (each with Copy), and for static colors a paste-ready **CSS override**. A search box finds a color by name or token (for example `--cds-support-info`). |
| **Brand** | The brand color, quick-pick colors, and the tokens it drives. |
| **Accessibility** | WCAG target (AA or AAA), auto-adjust, and the live contrast report. The tab badge shows a check or the error count. |
| **Export** | Effective palette, Copy CSS, Copy / Apply settings (JSON). |

Above the tabs: **Starting point** (Carbon, Ocean, Royal, Ember) and **Base theme** (white, g10, g90, g100,
the theme being edited).

Status, link and focus colors are marked *auto-adjusted* and have no verbatim CSS override: they feed the
token generator, which adjusts them to your WCAG target, so the applied value can differ slightly from the
one you pick.

Inputs: `showThemeColors`, `showAccessibility`, `showAdvanced` hide the Colors, Accessibility and Export tabs;
`defaultColor` and `presets` are unchanged. The tabs support the arrow keys, Home and End.
